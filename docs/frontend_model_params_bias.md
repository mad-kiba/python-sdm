# Параметры запуска модели и поправка human bias: задание для фронта

Источник данных — `{id}.json`, два независимых блока верхнего уровня: `model_params` (параметры алгоритма) и `bias_correction` (поправка на неравномерность наблюдений при выборке фона). Ни один из них не требует новых запросов к серверу — оба уже попадают в тот же файл, который фронт получает по модели.

## 1. Параметры алгоритма (`model_params`)

### 1.1. Формат

Поле `algorithm` всегда равно одному из значений ниже и однозначно определяет набор остальных полей.

**RandomForest**
```json
"model_params": {
    "algorithm": "RandomForest",
    "n_estimators": 500,
    "max_depth": 10,
    "min_samples_leaf": 5,
    "class_weight": "balanced_subsample",
    "random_seed": 42
}
```

**XGBoost**
```json
"model_params": {
    "algorithm": "XGBoost",
    "n_estimators": 500,
    "learning_rate": 0.05,
    "max_depth": 5,
    "subsample": 0.8,
    "colsample_bytree": 0.8,
    "scale_pos_weight": 5.0,
    "random_seed": 42
}
```

**MaxEnt** (адаптированное ядро библиотеки elapid — linear/hinge/product-признаки, L1-регуляризация)
```json
"model_params": {
    "algorithm": "MaxEnt",
    "implementation": "elapid (адаптированное ядро, см. sdm/utils/elapid_core/)",
    "feature_types": ["linear", "hinge", "product"],
    "beta_multiplier": 1.5,
    "class_weights": 100,
    "random_seed": 42
}
```

**GLM** (логистическая регрессия sklearn, линейные + квадратичные признаки, сила L2-регуляризации подбирается кросс-валидацией)
```json
"model_params": {
    "algorithm": "GLM",
    "features": "linear + quadratic",
    "class_weight": "balanced",
    "regularization": "L2",
    "C_selected_by_cv": 1291.5497,
    "cv_folds": 5,
    "random_seed": 42
}
```

### 1.2. Как показывать

Отрисовывайте таблицу «параметр / значение» по полям того алгоритма, который указан в `algorithm`. Названия полей — служебные (`n_estimators`, `reg_lambda`), поэтому давайте им подпись на русском, например:

| Поле | Подпись | Пояснение (можно во всплывающей подсказке) |
|---|---|---|
| `n_estimators` | Число деревьев | Сколько деревьев решений строит ансамбль |
| `max_depth` | Максимальная глубина дерева | Ограничивает сложность каждого дерева, защита от переобучения |
| `min_samples_leaf` | Мин. точек в листе | Подбирается автоматически по числу точек присутствия вида; чем меньше точек у вида, тем мягче ограничение |
| `class_weight` | Балансировка классов | Компенсирует то, что фоновых точек обычно намного больше, чем точек присутствия |
| `learning_rate` | Скорость обучения | Шаг градиентного бустинга |
| `subsample`, `colsample_bytree` | Доля строк/признаков на дерево | Снижают переобучение за счёт случайности |
| `scale_pos_weight` | Вес класса присутствия | Посчитан для конкретной модели как (число фоновых точек / число точек присутствия) |
| `random_seed` | Семя генератора случайных чисел | Фиксирует воспроизводимость обучения |
| `features` | Набор признаков (GLM) | `linear + quadratic` — используются и сами предикторы, и их квадраты |
| `feature_types` (MaxEnt) | Типы признаков MaxEnt | `linear`/`hinge`/`threshold`/`product` — какие виды признаков строит модель поверх исходных предикторов (hinge и threshold умеют описывать и немонотонный, и пороговый отклик) |
| `beta_multiplier` (MaxEnt) | Сила регуляризации | Чем выше, тем больше коэффициентов отбрасывается. Единственный настраиваемый параметр силы регуляризации в этой реализации |
| `class_weights` (MaxEnt) | Взвешивание присутствие/фон | Число — соотношение весов присутствие:фон (100 — как в R-пакете `maxnet`), либо `"balanced"` |
| `class_weight` (GLM) | Балансировка классов | `balanced` — компенсирует то, что фоновых точек обычно намного больше, чем точек присутствия |
| `C_selected_by_cv` (GLM) | Сила регуляризации | В отличие от MaxEnt, не задана заранее: подобрана 5-фолдовой кросс-валидацией по ROC AUC на обучающих данных конкретной модели — у разных видов будет разным, это нормально |
| `cv_folds` (GLM) | Число фолдов кросс-валидации | Сколько частей использовано при подборе `C_selected_by_cv` |

Поле `input_parameters.model_type` в JSON и так уже содержит то же название алгоритма — отдельно его повторять не нужно, `model_params.algorithm` достаточно для выбора нужной таблицы.

### 1.3. GLM и MaxEnt — разные модели, не путать

GLM — логистическая регрессия на линейных и квадратичных признаках с силой регуляризации, подбираемой кросс-валидацией. MaxEnt — адаптированное ядро библиотеки elapid: более богатый набор признаков (linear/hinge/threshold/product), L1-регуляризация (часть коэффициентов становится ровно нулём, а не просто маленькой), фиксированная сила регуляризации (`beta_multiplier`). Карточки параметров не объединять.

### 1.4. Какие алгоритмы поддерживают прогноз будущего/прошлого

Не все алгоритмы в `model_params.algorithm` одинаково участвуют в прогнозах будущего (`predict_future`) и прошлого (`predict_past`) — сейчас это только `RandomForest` и `XGBoost`. Если модель посчитана с `MaxEnt` или `GLM`, в `{id}.json` не будет блоков `future_stats`/`past_stats` вообще (эти шаги для них пропускаются сразу, без ошибки) — на фронте в разделах прогноза будущего/прошлого для таких моделей нужно показывать не «ошибка» и не пустой блок, а понятную фразу вида «Для этого алгоритма прогноз на будущее/прошлое не поддерживается».

### 1.5. Старые модели

Поле `model_params` появилось только сейчас. Если модель посчитана раньше и в её JSON блока нет — ничего не показывайте (не ошибка, не предупреждение), либо выведите общую фразу: «Параметры алгоритма не сохранены для этой модели».

## 2. Поправка human bias (`bias_correction`)

### 2.1. Форма запуска

- Поле `useBiasForBg` (0 или 1) и `biasStrength` (0–1). Подпись: «Поправка на неравномерность наблюдений при выборке фона».
- Сервер считает поправку включённой, если `useBiasForBg` не передан, поэтому фронт должен всегда передавать его явно.
- Полей, связанных с M-фактором (`useBiasForMF`, `mfBiasStrength`), в форме быть не должно: эта поправка из кода убрана полностью, а не только из JSON.

### 2.2. Формат в JSON

```json
"bias_correction": {
    "use_for_bg_sampling": 1,
    "bg_sampling_strength": 0.7,
    "bg_layer": "human_bias_Aves",
    "num_biased_bg": 525
}
```

| Поле | Значение | Как показывать |
|---|---|---|
| `use_for_bg_sampling` | поправка запрошена (0 или 1) | см. 2.3 |
| `bg_sampling_strength` | заданная доля случайного фона, выбираемая с учётом наблюдений | в процентах: 0.7 → 70% |
| `bg_layer` | использованный слой или `null` | см. 2.4 |
| `num_biased_bg` | сколько фоновых точек реально выбрано с учётом наблюдений | число |

Долю для расчёта процента от общего случайного фона возьмите в `background_sampling.num_random_bg`.

### 2.3. Статус поправки

Проверяйте условия по порядку, первое совпадение и есть статус:

| Условие | Текст |
|---|---|
| в блоке нет поля `bg_layer` | модель старого формата, см. 2.5 |
| `use_for_bg_sampling` ≠ 1 или `bg_sampling_strength` = 0 | «Поправка не применялась» |
| `bg_layer` = `null` | «Поправка запрошена, но не применена: слой не найден» (выделить как предупреждение) |
| `num_biased_bg` = 0 | «Поправка не применена: в области нет данных о наблюдениях» (выделить как предупреждение) |
| иначе | «Поправка применена» |

Для применённой поправки выводите, например: «Поправка применена: 525 из 750 случайных фоновых точек (70%) выбраны с учётом плотности наблюдений. Слой: птицы».

### 2.4. Названия слоёв

`human_bias_alls` — все классы, `human_bias_Aves` — птицы, `human_bias_Mammalia` — млекопитающие, `human_bias_Amphibia` — амфибии, `human_bias_Squamata` — чешуйчатые, `human_bias_Testudines` — черепахи, `human_bias_Insecta` — насекомые, `human_bias_Plantae` — растения, `human_bias_Fungi` — грибы.

Если класс вида не имеет своего слоя, используется `human_bias_alls`. Сообщать об этом отдельно не нужно: название слоя уже это показывает.

### 2.5. Старые модели

Признак — отсутствие поля `bg_layer`.
- Если `use_for_bg_sampling` = 1: «Поправка запрошена (доля N%), фактическое применение не записано. Модель рассчитана прежней версией».
- Иначе: «Поправка не применялась».

Поля `m_factor_strength` и `use_for_m_factor` могли встречаться в очень старых моделях — не показывать их ни в каком виде, они не отражают реальный расчёт.

### 2.6. Подсказка для пользователя

> Наблюдения распределены неравномерно: больше данных там, где больше людей. Поправка выбирает заданную долю фоновых точек с учётом плотности всех наблюдений GBIF, чтобы фон отражал такое же смещение. Остальные точки выбираются равномерно. На M-фактор поправка не влияет.

## 3. Пример совместного вывода

Оба блока лежат в одном файле на одном уровне и не связаны друг с другом — выводить их можно в разных местах карточки модели:

```json
{
    "model_params": {
        "algorithm": "RandomForest",
        "n_estimators": 500,
        "max_depth": 10,
        "min_samples_leaf": 5,
        "class_weight": "balanced_subsample",
        "random_seed": 42
    },
    "bias_correction": {
        "use_for_bg_sampling": 1,
        "bg_sampling_strength": 0.7,
        "bg_layer": "human_bias_Aves",
        "num_biased_bg": 525
    }
}
```
