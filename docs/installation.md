# Установка

Эта инструкция описывает установку и запуск библиотеки `sdm` как самостоятельного Python-модуля, без какого-либо фронтенда или HTTP-сервера. Серверная обвязка (`sdm_server.py` и т.п.) — это отдельный, необязательный способ использования модуля; сам модуль прекрасно работает и как обычный импортируемый пакет внутри произвольного скрипта.

## 1. Требования

- Python **3.9** или новее (на совместимость с более ранними версиями модуль не проверялся).
- Системные пакеты для растровых/графических зависимостей:
```
yum install python3 python3-pip libxcb mesa-libGL   # CentOS, RHEL
# или
apt install python3 python3-pip libxcb1 libgl1       # Ubuntu, Debian
```

## 2. Получение кода

Скачайте/склонируйте репозиторий в отдельную папку, например `python_sdm`. Внутри неё должна быть папка `sdm` (сам пакет), `examples` (минимальный пример и тестовые данные) и файлы `setup.py`, `requirements.txt`.

## 3. Установка зависимостей

Вариант А — просто поставить зависимости и использовать модуль прямо из исходников (как в `examples/example_minimal.py`, через `sys.path.insert`):
```
pip install -r requirements.txt
```

Вариант Б — установить сам пакет `sdm` (например, в редактируемом режиме, чтобы `import sdm` работал из любого места):
```
pip install -e .
```
или обычная установка:
```
pip install .
```

Полный список зависимостей (сверен с реальными импортами в коде): `numpy`, `pandas`, `scipy`, `scikit-learn`, `xgboost`, `rasterio`, `affine`, `pyproj`, `contextily`, `matplotlib`, `opencv-python`, `Pillow`, `joblib`. Точные версии — см. [requirements.txt](../requirements.txt) и `install_requires` в [setup.py](../setup.py).

Пакет `scikit-fmm` используется опционально для расчёта доступной территории ("M-фактора") методом Fast Marching через поверхность трения (cost-distance). Если он не установлен, расчёт M-фактора откатывается на более простые функции затухания от буфера наблюдений, без учёта барьеров рельефа/воды — остальной пайплайн работает без изменений.

## 4. Подготовка слоёв-предикторов

Модуль ожидает растровые предикторы в формате **GeoTIFF** (если в файле несколько каналов, используется только первый) в папке `input_predictors` на том же уровне, откуда запускается скрипт. Внутри неё до пяти подпапок:

| Подпапка | Назначение |
|---|---|
| `input_predictors/static` | предикторы, неизменные во времени (например, высота над уровнем моря) — используются и для текущего периода, и для будущего/прошлого |
| `input_predictors/dynamic_current` | предикторы текущего периода (например, биоклиматические переменные WorldClim) |
| `input_predictors/dynamic_predictable` | предикторы будущих периодов. Структура: `dynamic_predictable/<период>/<сценарий>/`, например `dynamic_predictable/2041-2060/ssp370/`. Для каждого файла из `dynamic_current` здесь должен быть одноимённый файл для каждого периода/сценария — иначе прогноз будущего для этого периода/сценария построить не получится |
| `input_predictors/dynamic_past` | предикторы прошлого (например, CHELSA TraCE21k). Структура проще: `dynamic_past/<период>/`, без сценариев (например `dynamic_past/02-180/`); отдельно обязательна подпапка `dynamic_past/learning/` с предикторами "настоящего" в том же формате, что остальные периоды прошлого — на них обучается отдельная модель для прогноза прошлого |
| `input_predictors/dynamic_monthly` | только если включён помесячный прогноз (`MODEL_SEASON = 1`): подпапка на каждый месяц (`1` … `12`) |

Для минимального запуска достаточно:
- `WorldClim elevation` (https://www.worldclim.org/data/worldclim21.html, разрешение `30 seconds`) → в `input_predictors/static`;
- `Bioclimatic variables` оттуда же → в `input_predictors/dynamic_current`.

## 5. Подготовка наблюдательных данных

Точки наблюдения вида передаются в формате CSV (структура соответствует экспорту с GBIF.org — используются колонки координат, даты наблюдения, точности координат и таксономии). Несколько минимальных примеров уже лежат в `examples/data`.

## 6. Проверочный запуск

Скопируйте содержимое папки `examples` (папку `data` и файл `example_minimal.py`) в корень проекта (туда же, где лежат папки `sdm` и `input_predictors`), и выполните:
```
python example_minimal.py
```
Будет запущена модель для сапсана (*Falco peregrinus*) на территории Алтая. Если всё настроено верно, в консоль будет выведено "Моделирование завершено", а в папке `output/` появятся карта пригодности (`output/suitability/1/`) и метрики (`output/texts/1/1.json`).

Что делает каждый шаг этого скрипта и что означают параметры конфигурации — см. [usage.md](usage.md).
